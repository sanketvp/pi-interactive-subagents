## Sandbox design (Q7): bypasses found

The receipt-socket/peer-PID design is sound *given* a sound sandbox and an uncompromised worker Pi process. Both preconditions have holes; the self-test (a–f) and adversarial #15/#18/#23b/#45 would not catch them, so a porous boundary would ship green.

1. **`(allow default)` deny-list profile leaks through launchd-mediated re-execution.** A sandboxed shell can run `open x.command` / `open -a Terminal`, `launchctl bootstrap gui/$UID <plist-in-registered-root>`, `osascript -e 'tell app "System Events" to keystroke …'`, or `at`; launchd/LaunchServices spawns the target **outside** the sandbox, which then does `tmux send-keys` to answer P5/P14. Also `TIOCSTI` on the inherited controlling tty injects keystrokes without tmux. None are in the self-test.
2. **Profile rule order is inverted for overlapping paths.** "Last matching rule wins" + denies emitted *before* `(allow file-write* (subpath <root>))` means a registered root that contains `~/.pi`, the session dir or `$TMPDIR` (e.g. root = `$HOME`) re-allows writes to them.
3. **Harness-side `git` is unsandboxed and honours repo config.** `artifact.ts`/`worktree.ts`/`triggers.ts` run `update-index`, `write-tree`, `diff`, `cat-file`, `ls-tree` in the real root; `.git/config` is writable by any author (G12 allows `.git/**`) or coordinator `write`. `core.fsmonitor` executes on every index op; `diff.external`/textconv on diff. That code runs as the harness, in the coordinator pane, unsandboxed → send-keys, read tokens/packets. Only `git_ro` (#21b) is hardened; #40 covers materialisation only.
4. **Worker Pi process trusts its cwd.** Verifier cwd = materialised tree, author cwd = repo. If Pi loads project-local `.pi/extensions|skills|settings` from cwd (must be verified against the Pi source), repo content executes in the unsandboxed worker process — inside a valid pane pid tree — so it can forge the "host" `verify_exec` ledger (the ledger lives in the verifier's own process, not the coordinator), forge its own completion receipt, and send-keys. A5's residual ("nothing else") is then false.
5. **Receipt socket path length.** `<sessionDir>/receipt.sock` under `~/.pi/agent/sessions/<long id>/` will typically exceed macOS's 104-byte `sun_path` limit → `bind` fails → gating `on` refuses every launch on day one.

Minor/residual (non-blocking): ancestor exit between `connect` and `ps` breaks the chain → false `receipt-rejected` (availability only; walk once more before rejecting). Symlinks materialised from blob bytes can point outside the tree; the verifier's unsandboxed `read/grep/find` will follow them (read-only, tokens are identifiers — state it, or materialise symlinks as plain files). `cacheDirs` (`~/.npm`, `~/.cache`) are a user-level supply-chain write path for later unsandboxed `npm/pip` runs — state in §16. `open`-style escapes also apply in shadow mode; shadow is non-enforcing, so acceptable.
