SYNTHESIS:

For SESSION PERSISTENCE + EXACT RESUME + TAKEOVER + CRASH RECOVERY:
1. **@tintinweb/pi-subagents** (PRIMARY RECOMMENDATION)
   - Session resume: ✓ (conversation context preserved)
   - Takeover (steer): ✓ (mid-run message injection)
   - Crash recovery: ✓ (graceful turn limits, completion notifications)
   - Worker state: ✓ (FleetView, event bus, RPC)
   - Coordination: ✓ (replaces/complements orchestration)
   - Limitation: Pi session scope only (no machine-restart persistence)

2. **pi-background-tasks** (COMPLEMENTARY)
   - Crash-safe task durability: ✓
   - Worker delegation: ✓ (child Pi processes)
   - Session resume: ✗ (undocumented)
   - Use case: Long-running shell tasks, Fusion workflows

3. **@mjasnikovs/pi-task** (COMPLEMENTARY)
   - Crash-safe task state: ✓
   - Deterministic recovery: ✓ (spec-driven DAGs)
   - Takeover: ✓ (remote web view monitoring)
   - Use case: Complex task pipelines, remote workers

ORCHESTRATION vs. REPLACEMENT:
- @tintinweb/pi-subagents: COMPLEMENTS orchestration (provides lower-level agent coordination; orchestration layer coordinates multiple subagent types).
- pi-background-tasks: COMPLEMENTS (task durability layer; orchestration dispatches tasks to it).
- @mjasnikovs/pi-task: PROVIDES ALTERNATIVE orchestration (spec-driven vs. agent-driven).

REQUIRED EVENTUAL BEHAVIOR ALIGNMENT:
- ✓ Pi-only model dispatch (all packages verified @earendil-works/pi-coding-agent compatibility)
- ✓ Visible interactive workers (FleetView, widget UI, remote web view)
- ✓ Single Orca tab (no new tabs; extensions handle internal paning)
- ✓ Exact session UUIDs (Pi session scope; machine-level UUIDs require custom storage)
- ✓ Safe steering/takeover (@tintinweb/pi-subagents: steer_subagent tool; @mjasnikovs/pi-task: web view)
- ✓ Failure handling (@tintinweb: graceful wrap-up; @background-tasks: durability; @task: verify gates)
- ~ Reload/recovery (@tintinweb resume supports Pi-level; machine restart requires custom persistence layer)
- ✓ Owned cleanup (event bus + lifecycle)
- ~ Customization preservation (no documented upgrade hooks; manual migration required)

---

LESSON:
No single extension provides universal session/worker state persistence across machine restart. @tintinweb/pi-subagents is the strongest foundation for recovery within a Pi session; pairing with pi-background-tasks or @mjasnikovs/pi-task provides task-level durability. A custom session checkpoint layer (storing UUID + agent state to persistent store) is required for cross-machine resume.

BLOCKERS:
None at extension discovery level. @mjasnikovs/pi-task's AGPL-3.0-only license requires review for commercial use.
